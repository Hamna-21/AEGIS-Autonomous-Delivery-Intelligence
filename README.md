# AEGIS Autonomous Delivery Intelligence

This workspace contains AEGIS, organized by project area.

```text
AEGIS/
├── data/          preserved instructor instance data
├── algorithms/    separate Part B algorithm modules and public exports
├── part_a/        Part A environment facade and runner
├── part_b/        Part B planning facade and compatibility API
├── part_c/        Part C adversarial modules
├── part_d/        Part D command assistant modules
├── part_e/        explicit pending-specification boundary
├── ui/            frontend shell, backend adapters, components and pages
├── experiments/   reproducible experiment runners
├── outputs/       raw data, figures and event logs
├── tests/         cross-part test suite
├── world/         Part A environment implementation modules
├── part_a.py      legacy Part A runner
└── common.py      legacy shared utility module
```

Compatibility facades preserve existing import paths while algorithms, parts,
and frontend modules remain separately organized.

The simple canonical entry points are `config.py`, `world.py`, `planners.py`,
`game.py`, `llm_agent.py`, `experiments.py`, `app.py`, and `run_all.py`.
They use the unchanged root `oel_instance.py`, derive the instance from the
CMS IDs in `common.py`, and write reproducible CSV, SVG, JSONL, and trace
outputs under `results/` when `python run_all.py` is executed.

The original instructor-generated instance metadata is stored in `data/instance.json`. The Part A loader uses a local `data/grid_64409bfc.npy` when present, and otherwise reads the unchanged NumPy grid directly from the supplied starter ZIP in Downloads. The grid is treated as input data and is never regenerated by the Part A code.

## Test commands

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m part_a.run
python run_all.py
python -m streamlit run app.py
```

## Current implementation

* Part A: grid, terrain costs, obstacles, fog, flood, slip, and movement rules.
* Part B: BFS, Uniform Cost Search, Depth-Limited Search, Iterative Deepening
  Search, Greedy Best-First Search, and A* with multi-stop state tracking.
* Part C: reduced adversarial game, Minimax, Alpha-Beta pruning, move ordering,
  stochastic execution, replanning, and confidence intervals.
* Part D: validated offline natural-language command tools with event traces.
* UI: Streamlit mission control with seven research and operations pages.
* Research: reproducible seeded experiments, raw CSV, summary tables, and SVG
  figures through `python run_all.py`.

Part E is not implemented in this workspace. The project does not claim a
provider-backed LLM. Part D uses an explicitly labelled `offline_parser` mode
when no API key is configured.
